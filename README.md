# Poker League

Простой статический калькулятор домашнего чемпионата: 8 игроков, 3 независимых раунда. HTML, CSS и JavaScript, без зависимостей, базы данных и сервера приложения.

## Использование

Откройте `index.html` или опубликованную страницу GitHub Pages. На MacBook можно открыть файл двойным щелчком. Для телефона удобнее публикация по HTTPS.

1. В разделе «Имена игроков» задайте имена.
2. Выберите раунд. При каждом вылете нажмите «Вылетел», затем внесите KO победителю или нескольким победителям (например, по `0,5`).
3. На финише введите стеки оставшихся игроков. Всего в игре 80 000 фишек.
4. Результат автоматически попадает в рейтинг, когда заполнены все результаты, сумма фишек правильна и KO распределены. До этого показывается «—», без ложных очков за неполный раунд.
5. Для исправления вылета выберите его номер; остальные номера сдвинутся. «Вернуть в игру» восстановит ранее введённый стек. KO редактируются отдельно.

Данные сохраняются после каждого корректного изменения в localStorage. Неверное поле не заменяет сохранённое значение. Данные разных браузеров, устройств, адресов и режимов приватного просмотра не синхронизируются. Хранение при открытии через `file://` зависит от браузера; для регулярной игры используйте постоянный HTTPS-адрес. Очистка данных браузера удаляет результаты.

«Экспорт JSON» сохраняет копию всех имён и трёх раундов; «Импорт JSON» проверяет формат и просит подтвердить замену. Перед импортом экспортируйте текущую копию, если она нужна. Повреждённое сохранение не перезаписывается; экспорт позволяет забрать исходную копию. При изменениях в другой вкладке автосохранение останавливается до обновления страницы.

## Правила и соответствие Excel

Изучены все 5 листов исходного `poker_players.xlsx`: «Рейтинг», «Раунд 1», «Раунд 2», «Раунд 3», «Правила». Исходные имена — «Игрок 1»…«Игрок 8»; результаты пусты. Скрытых листов, именованных диапазонов и Excel Tables нет. Исходный файл не изменён и не включён в публичный проект.

- «Правила» A5: 10 000 стартовых фишек каждому, без ребаев; всего 80 000. Проверяется сохранение общей суммы.
- «Правила» A9–A11; раунды E6:F13: выбывший с номером `n` занимает место `9 − n`. Оставшиеся ранжируются по стеку. Очки за 1–8 места: **12, 9, 7, 5, 3, 2, 1, 0**, плюс KO.
- «Правила» A17: равные стеки делят сумму очков соответствующих мест. Например, первое и второе места дают по `(12 + 9) / 2 = 10,5`. Исправлено расхождение с Excel, где COUNTIF присваивал всем одинаковое место и полные очки. В интерфейсе отображается диапазон занятых мест.
- «Правила» A16: общий рейтинг сортируется по очкам, затем победам, затем KO. Формула Excel G5:G12 учитывала только очки. При полном равенстве сохраняется одинаковое место; дополнительную игру проводят вне приложения.
- «Рейтинг» H5:H12 считает каждого игрока с первым местом победителем. Это сохранено для равных максимальных стеков: все делящие первое место получают одну победу. Правила отдельно не уточняют этот случай.
- «Правила» A15: неполный раунд не участвует в рейтинге. KO, победы и очки суммируются только по полностью введённым раундам.
- Дробные KO принимаются с точкой или запятой. Для деления на троих используйте `0,333333`, `0,333333`, `0,333334`; допуск проверки общей суммы — 0,000001. Вывод округляется до 6 знаков, расчёт выполняется без промежуточного округления.
- Стек — целое неотрицательное число до 80 000; нулевой стек требует отметки вылета. Одновременно действующий стек и вылет не учитываются. Порядок вылета всегда уникален, непрерывен, содержит максимум 7 игроков. Дубли имён запрещены. KO — от 0 до 7; сумма должна равняться числу вылетов. При нескольких вылетах в одной раздаче организатор задаёт их порядок — отдельного правила для этого Excel не содержит.

**Противоречие в источнике:** «Правила» A8 требует доиграть текущую раздачу после 50 минут, A19 — затем провести ещё одну финальную. Калькулятор не управляет временем и раздачами; договоритесь о варианте перед игрой. Это не влияет на формулы. Таймеры и блайнды намеренно не добавлены по запросу пользователя.

GitHub Pages публикует ветку `main`, папку `/ (root)`. Изменения файлов в этой ветке обновляют приложение после завершения сборки Pages. Сервер приложения и сборка JavaScript не нужны.

Локальные результаты автоматически на новый адрес не переносятся: экспортируйте JSON в локальном приложении и импортируйте его на опубликованной странице. На каждом устройстве данные хранятся отдельно.

## Проверка разработчиком

Node.js нужен только для запуска тестов: `node --test model.test.cjs`. Для использования приложения он не нужен.

Тесты покрывают очки Excel во всех трёх раундах, суммарный рейтинг, несколько вылетов, дробные KO, равные стеки, неполные результаты, сумму фишек, JSON и неправильные входные данные.

Файлы: `index.html` — страница, `style.css` — адаптивный интерфейс, `model.js` — расчёты и проверка данных, `app.js` — ввод и сохранение. Внешних запросов, аналитики и пользовательских аккаунтов нет.

Проверка 25.10.2026: 9 автоматических тестов пройдены. В браузере проверены все три раунда, дробные KO, изменение порядка вылетов, обновление страницы с сохранением данных, экспорт и восстановление JSON, отклонение неверного JSON и отрицательного стека. На ширине 390 px проверены поля и рейтинг: горизонтальной прокрутки нет. Проверка на физическом iPhone и в Safari на MacBook не проводилась. Тестовые результаты очищены.
